# TextDraw Studio — этап 3.1: слои, выделение и группы

База: `feat/tdstudio-interactive-move`, `e173eab` (PR #55, основа PR #42).
Рабочая ветка: `feat/tdstudio-advanced-layers-stage31`. Этапы 3.2/3.3 не реализуются.
Контрольная компиляция базы выполнена до изменений: 0 ошибок и предупреждений.

## Управление

Открыть `/tdstudio`, создать/загрузить проект, выбрать «Редактировать интерфейс».
Прежние создание, свойства, холст, предпросмотр, шаг и закрытие сохранены.
Добавлены разделы «Слои», «Выделение», «Группы» и действие дублирования.

| Раздел | Действия |
| --- | --- |
| Слои | список от заднего к переднему, поднять/опустить, на передний/задний план |
| Выделение | переключатели в списке, режим MULTI для мыши, выделить все, снять выделение |
| Группы | создать из выделения, выбрать целиком, переименовать, состав, расформировать, переместить, слои группы |
| Дублирование | независимая копия активного элемента, также из его свойств |

Список элементов показывает слой L, постоянный ID, тип, группу G и выделение.
L0 — задний слой; больший `tdOrder` ближе к переднему плану. Свойства и точные
координаты доступны после выбора строки. Все списки рассчитаны на 64 элемента
и максимальные ID: тело меньше 4096 символов, заголовок до 63 символов.

Одиночный клик и обычный список выбирают один элемент. В режиме MULTI каждый
клик добавляет/убирает элемент; доступны аналогичные переключатели в списке.
Последний добавленный элемент — активный для свойств/дублирования. Снятие его
выделения переводит фокус на другой выбранный элемент. Счётчик SEL показывает
выделенное количество относительно количества элементов проекта. Ctrl/Shift
не используются. Выделение и активный фокус не сохраняются в проект.

Для логотипа выделить хотя бы два элемента без других групп, выбрать «Группы →
Создать» и ввести, например, `TARKENSO_LOGO`. Имена 1..32 символа, уникальные
в проекте, с теми же безопасными ограничениями, что имена проектов. Вложенных
групп нет. Членство другого элемента сначала нужно убрать из прежней группы.
В разделе «Состав» видны все элементы; [+] означает принадлежность этой группе.
Строка переключает включение/исключение. Пустая группа автоматически удаляется;
группа из одного оставшегося элемента допустима. Расформирование требует
подтверждения и сохраняет все элементы, свойства, координаты и слои.

«Выделить всю группу» включает всех её участников. Панель показывает имя, ID,
количество выбранных участников и шаг. Одиночное редактирование участника остаётся
доступным через обычный выбор; явный выбор группы снова собирает весь состав.
«Переместить группу» сразу включает клавиатурный режим. Также можно нажать
верхнюю строку на холсте или выбрать «Перемещение выделения» в меню.

Управление из этапа 2.1: игровые направления GTA (обычно WASD/стрелки),
Enter/Y — подтвердить, N или `/tdstudio` — отменить, Space — следующий шаг
0.1/0.5/1/5/10. После входа/паузы нужен нейтральный пакет с отпущенными клавишами.
Это действия GTA, а не физические keycodes. Esc без TextDraw-курсора не поступает
серверу. Выбор мышью и экранные X/Y-кнопки сохранены; кнопки двигают текущее
выделение, а свойства меняют только активный элемент.

## Модель и архитектура

- `tdId` остаётся постоянным ID элемента. `tdOrder` задаёт единственный порядок
  для списка, рендера, сериализации и экспорта. ID не меняются при смене слоёв.
- `tdGroup` — ссылка на логическую группу или 0. `E_TDS_GROUP` содержит ID и имя.
  Лимиты: 64 элемента, 16 групп, 8 изолированных сессий. ID групп уникальны
  внутри проекта, выдаются монотонно и не переиспользуются после удаления.
- Выделение `gTDSPicked`, режим MULTI и активная группа находятся в состоянии
  редактора отдельно от сериализуемых свойств. Групповые move-снимки хранят
  исходные ID и Float X/Y каждого участника отдельно от рабочей модели.
- `tdstudio_layout.inc` содержит операции выделения/групп/слоёв/дублирования;
  `tdstudio_layout_ui.inc` — их диалоги. Существующий `tdstudio_input.inc` расширен
  до ограниченного набора целей; codec/DB/renderer сохранены и расширены.

### Слои и ресурсы

Вверх/вниз выбранные непрерывные участки пересекают по одному соседнему
невыделенному элементу. Это детерминированно и для группы с разнесёнными слоями.
На передний/задний план используется стабильное разбиение: внутренний порядок
выбранных и остальных элементов сохраняется, выбранные образуют один блок.
После изменения порядковые значения нормализуются в 0..N−1 без дублей.
Повторная команда на крайнем слое ничего не выделяет/пересоздаёт и не меняет dirty.

Смена порядка требует новых PlayerTextDraw-хэндлов. Сначала выделяются и полностью
настраиваются скрытые хэндлы в нужном порядке, пока старые остаются живы.
Только после успешного выделения всего набора старые уничтожаются, новые
показываются. При отказе уничтожаются только временные хэндлы, восстанавливаются
прежние `tdOrder`; старый интерфейс и выделение остаются. Потребуется запас до N
дополнительных PlayerTextDraw на время операции; лимит движка — 256 на игрока.

Проверены [документация open.mp](https://open.mp/docs/scripting/resources/textdraws),
[клиентские лимиты](https://open.mp/docs/scripting/resources/limits) и реализация
пула [open.mp SDK](https://github.com/openmultiplayer/open.mp-sdk/blob/master/include/Impl/pool_impl.hpp):
он выделяет минимальный свободный индекс. Создание временного набора без
освобождения старых даёт возрастающие ID в порядке слоёв. Harness проверяет
соответствие хэндлов этому порядку; реальное наложение шрифтов/моделей остаётся
сценарием визуальной приёмки GTA.

Дублирование копирует все свойства, строку, спрайт и preview-параметры, выдаёт
новый ID и ставит копию непосредственно над оригиналом. Смещение +10/+10
ограничивается якорными координатами X 0..640, Y 0..448, как в прежнем редакторе.
Копия не входит в группу оригинала и становится единственным выбранным элементом.
Проверка лимита выполняется до изменения; ошибка выделения откатывает порядок,
счётчики и ID. Последующее изменение копии независимо от оригинала.

### Перемещение набора

Все цели и их хэндлы проверяются до записи координат. Каждому участнику
применяется один и тот же вектор. У группы вектор целиком ограничивается первым
участником, достигающим границы; при блокировке направления останавливаются
все, включая диагональ. Относительное расположение сохраняется с точностью Float.
Границы относятся к якорям TextDraw, а не к полному прямоугольнику его размеров.

На подтверждении dirty меняется только при фактическом изменении позиции.
На отмене сначала восстанавливаются координаты всех участников в модели, затем
пересылаются их позиции. Прежний dirty сохраняется. Перерисовываются только
двигаемые элементы и статус, без новых хэндлов/таймеров. Частота прежняя — до
20 Гц; большой перерыв ввода требует снова отпустить клавиши, без догоняющего скачка.

Конфликтующие изменения выделения, слоёв, состава, сохранение и экспорт запрещены
во время движения; редактирование запрещено на время DB-задания. Закрытие,
disconnect, смена прав/состояния и shutdown освобождают курсор, собственную
блокировку управления и временные снимки. Чужая административная/гоночная
заморозка не снимается. SQL при каждом движении не выполняется.

## MySQL и совместимость

Новая миграция: **`db/migrations/015_tdstudio_groups.sql`**. В проверенном актуальном
main номера 013/014 уже заняты LoadTest/LoadNet. Их файлы и механики не добавлялись
в эту ветку. Для 015 достаточно существующей схемы 012; 012 не менялась.

| Сущность | Изменение |
| --- | --- |
| `tdstudio_projects` | `next_group_id`, DEFAULT 1, CHECK границ |
| `tdstudio_groups` | PK (project_id,group_id), уникальное имя в проекте, FK проекта |
| `tdstudio_group_members` | PK (project_id,element_id), индекс группы, составные FK элемента и группы |
| Формат | версия 2; версия 1 читается с пустыми группами |

Составные FK исключают чужие элементы/группы, PK членства — одновременное
включение элемента в несколько групп. Удаление элемента/проекта каскадно удаляет
связи. Имена хранятся CP1251; транспорт строк — ограниченные HEX-литералы.

Существующие v1-процедуры не изменяются. Добавлены `tds_save_v2` и `tds_load_v2`.
Первый CALL выполняет одну транзакцию для метаданных, элементов, групп и связей,
с прежними FOR UPDATE, владельцем/привилегией основателя и ожидаемой ревизией.
Любая ошибка откатывает весь снимок. v1-писатель отказывается обновлять формат 2,
поэтому старая версия AMX не может незаметно стереть группы.

Скалярный wire элементов прежний: 27 полей и HEX текста. Группы передаются
отдельным ограниченным JSON `[group_id,name_hex,[element_id,...]]`; сам `tdGroup`
восстанавливается из связей. Используются прежнее подключение R41 и асинхронные
задания. R41 не имеет protocol prepared/bind API: типизированные процедуры и HEX
сохраняют прежнюю защиту строк без добавления библиотеки/подключения.

Загрузка читает один согласованный SELECT, валидирует весь снимок, ID, имена,
состав, количество и порядок, затем выделяет временные хэндлы. До успешного
завершения текущая модель не заменяется. Версия 1 становится рабочей версией 2
с пустыми группами; обновление записи происходит только при следующем сохранении,
с обычной проверкой ревизии. Save As сохраняет group IDs внутри нового project ID,
имена, состав, порядок и следующие счётчики, не меняя источник.

Привязка DB-ответов к аккаунту/токену/аренде и ограничение восьми заданий сохранены.
Поздний ответ после закрытия не может восстановить группы в новой сессии.

### Установка

1. Сделать резервную копию БД; убедиться, что 012 уже применена. Нужен MySQL 8.0.16+.
2. Применить **015 один раз** миграционным пользователем (ALTER/CREATE TABLE,
   CREATE ROUTINE и запись в schema_migrations). Обычные MySQL DDL имеют implicit
   commit; прерывание миграции требует проверки оператора перед повторным запуском.
3. Runtime-пользователю прежнего подключения нужны CRUD на новых таблицах и EXECUTE
   на `tds_save_v2`/`tds_load_v2` плюс прежние права. SQL SECURITY — INVOKER.
4. Установить собранный `compiled.amx`. Без schema_migrations.version=15 сохранение
   и загрузка отключаются с сообщением, рабочее редактирование остаётся в памяти.

На игровом хостинге миграция не применялась. Новых зависимостей, настроек
хостинга, сторонних подключений и изменений существующих CI-файлов нет.

## Pawn-экспорт

Генератор продолжает использовать `TDS_Order`: группы разворачиваются в обычные
TextDraw без дополнительной runtime-сущности. ID, комментарии порядка, координаты
и свойства каждого элемента сохраняются. Global/Player варианты и функции
Create/Show/Hide/Destroy/Hit прежние. Кириллица и экранирование не менялись.

Реальный пример генератора: [tdstudio_grouped_player_example.inc](examples/tdstudio_grouped_player_example.inc).
В исходном проекте две группы; результат содержит шесть обычных элементов в
порядке **5,6,1,2,3,4**. Четыре элемента логотипа имеют подтверждённые координаты
**11/19, 31/39, 51/59, 71/79**. Репозиторный пример декодирован в UTF-8;
runtime-экспорт по-прежнему CP1251. Подключение — по инструкции этапа 2/соседнему
`.txt`, через фиксированный `scriptfiles/tdstudio_exports`, без пользовательских путей.
