# Проверка пересечения ID диалогов

В Build добавлен обязательный шаг **Check dialog ID collisions** сразу после
Checkout, до установки runtime и скачивания компилятора. При ошибке сборка
останавливается; выпуск `compiled-output` не выполняется.

Локальный запуск из корня репозитория:

```sh
python3 tools/check_dialog_ids.py
python3 -m unittest discover -s tests -p 'test_dialog_ids.py' -v
```

Проверяются все `.pwn` и `.inc` внутри `gamemodes`, включая модули в подкаталогах.
Анализатор извлекает второй аргумент `ShowPlayerDialog` и автоматически находит
функции-обёртки, передающие ID параметром. Поэтому `TDS_Dialog` и
`AuthDialog_Present` проверяются вместе с прямыми вызовами. Новые обёртки и
цепочки обёрток не требуют добавления в ручной список.

Поддерживаются объектные `#define`, алиасы, простые скалярные `const`/`enum`,
целочисленные выражения, обе ветви тернарного выбора, десятичные/hex ID и
многострочные вызовы. Повторный показ одной именованной формы, её явный алиас,
комментарии, строковые литералы и посторонние числовые константы не создают
ложных конфликтов. Неиспользуемые FIRST/LAST-маркеры диапазона не считаются
отдельными окнами. Разные именованные формы с одинаковым ID блокируются,
включая формы внутри одного файла.

При конфликте выводятся число, обе константы, файлы и строки, например:

```text
DIALOG-ID ERROR: duplicate dialog ID 7100: SHIP_MAIN (ship.inc:1); TDS_MAIN (tds.inc:1)
```

Диапазон ID при показе — 0–32767 по open.mp API; отрицательное значение
считается закрытием диалога и не регистрируется как окно.

Это консервативный анализ исходников, а не полный препроцессор Pawn: проверяются
все ветви условной компиляции. Неопределённые/неоднозначные константы,
динамические ID из массива/игрока/результата функции, циклы, арифметическое
переполнение и неподдерживаемые выражения дают ошибку. Генерирующие диалоги
function-like macros и переопределение `ShowPlayerDialog` также отклоняются;
используйте обычную функцию-обёртку. Простой пропуск неразобранного ID или
список исключений для конфликтов отсутствуют.

Проверка охватывает статически выраженные окна в исходниках мода. Она не
проверяет сторонние бинарные filterscripts/plugins, резервирование пустых
промежутков диапазонов или корректность всей логики `OnDialogResponse`.
Компиляция Pawn и игровая проверка маршрутизации по-прежнему необходимы.

При добавлении окна выбирайте свободный ID, объявляйте именованную константу
и используйте её при показе и обработке ответа. ID, вычисляемые во время игры,
нужно заменить явным набором констант либо расширить анализатор с тестами.

Для текущего кода проверка установила: **80 файлов, 109 вызовов, 99 используемых
ID, 2 автоматически обнаруженные обёртки, 0 ошибок**. В тестах воспроизведены
оба прежних конфликта: корабль/контейнеры на 6340 и корабль/TDS на 7100.
Проверено, что CLI возвращает код 1 и указывает оба файла. Все 24 новых теста
проходят; полный регрессионный набор — 471 тест, без падений и ошибок.
Игровой код и текущие ID диалогов этим изменением не меняются.
