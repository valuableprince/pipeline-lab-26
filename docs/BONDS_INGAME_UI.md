# TARKENSO /bonds — игровой интерфейс инвестора

Рабочий интерфейс для граждан, добавлен в накопительный **PR #94** поверх
GOV-00—GOV-03. Приёмка всей системы — после GOV-06, раньше миграции
на рабочей базе не применять.

## Открытие

В игре введите **/bonds**. Команда доступна авторизованному игроку
в любом месте (до отдельного здания казначейства). Требуется работающий
MySQL-primary, миграции 017—021 и готовый GOV-03. В файловом режиме
команда корректно сообщает о недоступности.

Используются стандартные open.mp диалоги с зарезервированными ID
**6700—6706**. Отдельный TextDraw и клиентские файлы не нужны.
Диалоги учитываются в общей проверке коллизий ID в CI.

## Пошаговая покупка **ровно одной** облигации

1. Введите `/bonds`.
2. Выберите **«Доступные государственные займы»**.
3. На экране отображаются открытые выпуски с оставшимся количеством,
   номиналом и доходностью в базисных пунктах; по десять на странице,
   доступны «Следующая / Предыдущая страница».
4. Выберите выпуск. Система **повторно** читает актуальные условия из
   MySQL: название, номинал, доходность за весь срок, UTC дату погашения,
   покрытие страховки и страховой взнос.
5. Нажмите **«Купить 1»**.
6. В отдельном окне проверьте цену одной облигации и кошелёк.
   Нажмите **«Подтвердить»**. Отмену можно нажать без списания денег.
7. До завершения SQL-транзакции вы увидите лишь «Заявка отправлена».
   Сообщение **«Покупка 1 облигации подтверждена»** выводится только
   после получения фактического ответа сервера MySQL.

Сумму, игрока, цену, доход и количество нельзя подменить средствами
диалога: обработчик фиксирует **quantity=1**, привязывает операцию
к авторизованному SQL account ID, а `gov_bond_buy` ещё раз проверяет
достаточность денег, срок размещения, максимальный объём и лимит
количества на аккаунт.

При недостатке денег или превышении лимита MySQL выдаёт
подтверждённый `ROLLBACK`, а игрок получает понятный отказ.
**Неудача покупки не должна отключать весь сервер**:
для таких бизнес-отказов добавлен отдельный обработчик ошибки
`BondSettlement_OnError` с безопасным снятием блокировки кошелька.
Неизвестные сетевые результаты по-прежнему обрабатываются fail-closed,
так как списание могло успеть подтвердиться без ответа клиенту.

Повторная отправка того же диалога не создаёт новую покупку:
подтверждение потребляется однократно до запуска операции.
Повтор в SQL с тем же `event_key` также идемпотентен.

## Портфель

`/bonds` → **«Мой инвестиционный портфель»**.

Показываются из реестра:
- Код выпуска.
- Количество принадлежащих игроку бумаг.
- Номинал одной бумаги, ставка за срок.
- Состояние долга (включая дефолт).
- Остаток основного государственного долга.
- Доступная подтверждённая выплата, если она есть.

В каждой позиции можно выбрать **«Получить»** и подтвердить
перевод заблокированной в казне суммы на собственный кошелёк.
При заполнении кошелька перевод ограничен оставшимся до
`ACCOUNT_MAX_MONEY` пространством; не полученная часть сохраняется
в escrow и доступна позднее. Чужие выплаты получить нельзя:
SQL `gov_bond_claim_collect` строго проверяет owner account.

Если сервер начислил выплаты, пока игрок отсутствовал, они будут
отображены после следующего входа без потери средств.
Список и карточка считываются из SQL на каждом открытии,
не из несинхронизированного массива Pawn.

## Важные ограничения

- Команда доступна только для реальных **OFFERING** выпусков,
  которые уже созданы и утверждены в GOV-02. Без них список пуст.
  Меню **не создаёт фиктивные демонстрационные облигации**.
- До полной системы GOV-05 нет отдельного интерфейса министра
  финансов для создания выпусков. Внутренний GOV-02 API существует,
  но выдача полномочий будет в следующих этапах.
- Одна кнопка означает одну облигацию. Для нескольких бумажных единиц
  операцию можно повторить, соблюдая государственный лимит владения.
- Для неоплаченного остатка после дефолта GOV-04 реализует отдельную
  процедуру дальнейшего погашения и/или реструктуризации.
- Капитализация страхового фонда и выпуск бумаг **не создают деньги**.
- Не применять миграции 018—021 к production до общей приёмки GOV-06.

## Контрольные проверки

1. `/bonds` до авторизации / без MySQL — отказ без списания.
2. Нет OFFERING → пустой список с работающей кнопкой «Назад».
3. Есть OFFERING → список, актуальная карточка и подтверждение одной бумаги.
4. Купить одну → `government_bond_orders` +1, `holdings` +1,
   кошелёк минус номинал, казна плюс номинал, фонд плюс взнос.
5. Двойной ответ в диалоге → ровно одна покупка.
6. Недостаток денег / распродажа / лимит владения → отказ,
   без изменения балансов и без отключения остальных игроков.
7. Два игрока берут последнюю бумагу → только один получает право.
8. `/bonds` → портфель, достоверное число бумаг, владельцы не смешиваются.
9. Погашение в отсутствие игрока → отображение escrow после возвращения.
10. Получение выплаты дважды → только один перевод; второй — отказ.
11. Кошелёк близок к лимиту → частичное получение без переполнения.
12. Переподключение / поздний MySQL callback → нельзя применить
    денежную операцию к другой сессии.
13. Проверка CI не обнаруживает пересечений диалоговых ID 6700—6706.
14. Pawn компилируется без ошибок и предупреждений,
    MariaDB GOV-00—03 UAT проходит в изолированной среде.
