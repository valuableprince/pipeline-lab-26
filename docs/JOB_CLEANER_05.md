# JOB-CLEANER-05 — редактор контейнеров и навигация уборщика

## Требования к развёртыванию

**Сначала** сделайте резервную копию MariaDB. Остановите сервер и примените `db/migrations/010_cleaner_container_editor.sql` после успешной установки версий 1–9. Новая схема v10 переносит контейнер ID 1 из `cleaner_container` с **текущими** `bin_units` и `overflow_units`; старую таблицу оставляет для отката, но новая версия мода её не обновляет. Затем установите AMX из успешного GitHub Actions и перезапустите open.mp. **AMX версии v10 не запускайте с БД v9** (защита старта).

## Редактор

В игре: войти под основателем Veyran, включить `/aduty`, завершить сюжетный пролог, выйти из машины, быть в обычном мире 0/интерьере 0, затем **`/studio containers`** или `/studio` → «Мусорные контейнеры».

Выберите «Создать контейнер» или ID имеющегося, откройте стандартный редактор и подтвердите положение объекта стрелками и галочкой. Затем откройте список десяти мест под мешки: каждый мешок ставится тем же редактором. После завершения сохраните позиции в MariaDB. Мешки, показанные **только основателю** в черновике, исчезают после сохранения. В обычном мире они появляются **только при переполнении**. Количество постепенно растёт по мере накопления до десяти штук.

Список поддерживает до 24 контейнеров, каждый имеет независимые координаты, 60 единиц внутри + 40 единиц наружного накопления, до 10 мест для мешков. Пустой контейнер, не являющийся последним, можно удалить. Заполненный удалять запрещено. Каждая операция журналируется. Объекты общей карты переиздаются **только после SQL COMMIT**. Редактирование ограничено основателем, вне гонок/пролога/деморгана. В этом релизе контейнеры можно устанавливать только в world 0, interior 0.

## Работа уборщика

Заполнив свой BAG, игрок получает сообщение и красную персональную отметку на карте — ближайший включённый контейнер с достаточной общей остаточной ёмкостью. Навигация уточняется раз в три секунды, когда игрок работает с полным мешком: полностью загруженный контейнер пропускается. После сдачи, окончания смены, релога или респавна метка удаляется. Чекпоинты профессий, гонок и сюжета не используются (`SetPlayerMapIcon`, а не `SetPlayerCheckpoint`).

При `/trashdrop` используется ближайший контейнер в зоне взаимодействия. Транзакция MariaDB объединяет защищённое увеличение его счётчиков и сохранение XP/заработка уборщика. Если сохранение завершается неуспехом — `ROLLBACK` и мешок остаётся у игрока. Муниципальная команда `/trashservice` очищает ближайший контейнер основателем с аудитом.

## Проверки перед открытием

Протестировать создание, отмену стрелками/ESC, настройку нескольких мешков, сохранение и перезапуск, удаление пустого и отказ при заполнении. Проверить реальное положение объекта и высоту мешков в GTA SA. Отдельно проверить полный контейнер, переключение красной отметки, несколько одновременных уборщиков и сохранение оплаты при принудительно недоступной MariaDB. SQL-миграция не выполняется автоматически средствами GitHub.
