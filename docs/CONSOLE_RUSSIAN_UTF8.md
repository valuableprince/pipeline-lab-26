# TARKENSO — русские сообщения в консоли open.mp

## Что изменено

Игровые тексты TextDraw, диалогов и чата по-прежнему компилируются
**в CP1251** — этого требует совместимость с SA-MP / клиентом GTA SA.

Для **сообщений игрового скрипта, направляемых в консоль**, добавлен
`ConsoleRU_Log()`: он преобразует CP1251-строку в UTF-8, передаёт её
обычному `print()` и дополнительно сохраняет такой же текст в файл,
который можно просматривать любым редактором с кодировкой UTF-8.

Это не изменяет кодировку всего open.mp, его внутренних сообщений,
чат-лога движка, сторонних плагинов или панели игрового хостинга.

## Проверка после установки compiled.amx

1. Обнови `gamemodes/compiled.amx` и **полностью перезапусти** сервер.
2. Найди в консоли строку (пример):

   ```text
   [TARKENSO] Проверка кодировки: Привет, мир! Ёж, №1, —.
   ```

3. Затем открой `scriptfiles/console_ru_utf8.log`. Файл содержит
   строки UTF-8; дата задаётся обычным серверным логом, а этот файл
   дополнительно хранит сам текст.
4. Авторизуйся обычным аккаунтом; при медленном этапе входа
   (`>=100 мс`) увидишь сообщение вроде:

   ```text
   [AUTH-PROFILE] Медленный этап bcrypt_verify_callback: 410 мс, ID=0 (время ожидания, не CPU)
   ```

   В `scriptfiles/auth_profiles/YYYY-MM-DD.csv` остаются полные
   числовые метрики авторизации.

Если **в UTF-8 файле всё корректно**, но в веб-консоли вместо кириллицы
показываются символы `????` или кракозябры, проблема в рендеринге
**терминала/панели хостинга**. Игровой AMX не может принудительно изменить
кодировку веб-интерфейса хостинг-провайдера. Проверь настройки кодировки
панели или покажи файл `console_ru_utf8.log` техподдержке.

## Для новых консольных сообщений

```pawn
ConsoleRU_Log("[WORLD] Игровой мир загружен.");

new message[128];
format(message, sizeof(message), "[AUTH] Игрок ID=%d успешно вошёл.", playerid);
ConsoleRU_Log(message);
```

Не выводи пароли, токены доступа, хеши, полные IP и персональные данные.
Исходники сохраняются **в UTF-8** в GitHub и конвертируются в **CP1251**
на этапе компиляции, как и прежде.

**Важно:** `print("Русский текст")` напрямую остаётся небезопасным
для UTF-8 консоли; используй `ConsoleRU_Log`. `printf` со строкой
из CP1251 напрямую также не перекодирует кириллицу.

Для диагностики принудительно используй `print` или `printf` только
с ASCII либо `ConsoleRU_Log` для кириллицы.

Новые миграции БД и плагины не нужны.
