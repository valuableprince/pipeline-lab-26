# CRIME-03.7 — финальный аудит, рейтинг синдикатов, баланс

Проект: TARKENSO RolePlay Game, open.mp/Pawn. Рабочая ветка:
`feat/crime02-solo-contract-core`, draft PR #111.

## 1. Новый игровой раздел

**`/crime → Рейтинг синдикатов`** отображает три собственные
организации: **Гавань (ID 6), Вектор (ID 7), Орион (ID 8)**.
Это не шаблонные банды GTA. Страница доступна любому
авторизованному участнику любого из этих синдикатов.

| Результат | Очки | Условие достоверности |
|---|---:|---|
| Победа в общей гонке CRIME-03.1 | +5 | `crime_competition_rounds.state=2` и фактическая запись в `crime_contract_rewards` |
| Доставленный тендер CRIME-03.2–03.4 | +3 | `crime_contracts.mode_id=3, state=3` и запись выплаты |
| Обычная одиночная перевозка | 0 | Не относится к соревнованиям |
| Победа в конкурсе заявок, но без доставки | 0 | Выбор NPC сам по себе не награждает |
| Влияние, активы и оперативные сводки | 0 | Побочные ресурсы не являются конкурентным рейтингом |
| Проигрыш в гонке или непринятая заявка | 0 | Фиксируются для истории, но не дают отрицательных очков |

При равенстве очков выше ставится синдикат с большим количеством
побед в гонках, далее — с большим количеством доставленных
тендеров, далее — по ID 6/7/8. Шкала не зависит от числа
одновременно подключённых игроков и не требует соперника.
Поражения считаются по `RACE_LOST` и `crime_tender_bids.state=3`.
Кнопка «История» показывает последние 12 подтверждённых событий:
победы и поражения гонок, доставленные и сорванные тендеры,
отклонённые заявки.

**Рейтинг ничего не записывает в БД.** Он использует только существующие
таблицы и FK/уникальные записи. Нет дополнительной миграции:
последняя необходимая миграция по-прежнему **046**.
Расчёт производится только при явном открытии раздела, без
постоянного таймера, фоновых пересчётов и сессионного кэша рейтинга.

## 2. Аудит экономики и безопасности

- Денежная награда учитывается в рейтинге **только при наличии
  записи в `crime_contract_rewards`**. Открытая заявка,
  проигрыш, отказ и просто выбранное предложение NPC награды
  не дают. Запись выплаты уникальна по `contract_id`.
- В соревновании в SQL сериализуется один `winner_contract_id`
  на `round_id`; для тендера уникален `tender_id` контракта.
  Рейтинг читает эти факты и не меняет их.
- В проверках CRIME-03.7 заданы сценарии 0, 1, 2 и 3 претендентов;
  первенство тендера определяется по `offer_code, bid_id`.
  Это **логические проверки баланса**, а не измерение реального
  количества игроков на игровом сервере.
- Тендерные коэффициенты сохранены (70%, 85%, 100%),
  длительности 15/25/40 минут, возможная доплата за
  рискованный исход — $300. Новых денежный источников нет.
  Дальнейшее изменение коэффициентов отложено до GTA UAT
  с замерами фактического времени прохождения.
- SQL-правила безопасности и статические проверки,
  уникальность ID диалогов, регрессионные тесты
  государственных облигаций и финансов, а также Pawn/AMX
  сборка остаются обязательными для PR.
- Встроенный MariaDB UAT выполняет *реальные SQL-запросы
  из Pawn-модуля рейтинга*, сверяет их с независимыми
  выборками из журналов, повторяет чтение 20 раз
  и убеждается в отсутствии новых выплат, событий и раундов.
  Время чтения выводится как **наблюдаемый показатель**
  без выдуманного абсолютного SLA.

## 3. Угроза повторных действий и изоляция доступа

Диалоги сверяют `gAuthToken`, `gDBPrimaryAccountId`,
фактическое членство в синдикате и одноразовый
`gCrimeUIDialog`. Игрок может смотреть историю других
синдикатов, но не может начислять себе или им очки.
Данные не берутся из клиентских событий и не записываются
в пользовательские аккаунты.

## 4. Что предстоит проверить непосредственно в GTA

Автоматические проверки **не заменяют** ручную приемку:
координаты и высоты NPC, фактическую скорость маршрутов,
переходы по клавише Y, сессии и диалоги нужно проверить
на реальном сервере с тестовой БД. Для единого прохождения:

1. Сделать резервную копию базы и остановить тестовый сервер.
   Применить миграции **031–046 последовательно**.
2. Убедиться, что три синдиката существуют, назначения
   рангов 1–5 работают и посторонние организации не изменены.
3. Проверить одиночные перевозки, расследования, улики,
   свидетелей, доверие, внимание и восстановление после релога.
4. Проверить обе физические стадии тендерных перевозок,
   осторожные/рискованные исходы, просрочку, невозможность
   пропустить обязательную точку и уникальность выплаты.
5. Проверить участие в общей гонке одним игроком, затем
   двумя и тремя синдикатами: один победитель, проигравшим
   деньги не начисляются.
6. Проверить заявки на тендер без конкурентов и с двумя/тремя
   конкурентами, порядок выбора NPC, возможность завершения
   в одиночку и ограничения по репутации.
7. Проверить оперативные сводки и восстановление связей:
   длительность 30/20 минут, таймауты, единичное начисление,
   разные исходы и ограничения 60 минут.
8. Проверить рейтинг (5/3 очка), все три организации,
   историю, пустую историю, сортировку при равенстве,
   правильное состояние после перезахода и отсутствие
   изменений денег при повторном открытии страницы.
9. Сверить цены, время реального прохождения маршрутов,
   денежную массу/инфляцию и нагрузку при 1, 2, 3 и
   десятках игроков. Любую найденную проблему исправить
   **до** слияния PR #111 в `main`.
