# ADMIN-01: административные права

Все команды проходят Pawn.CMD и проверку авторизации. Admin_Require повторно
проверяет право и включённый /aduty. Панель /admin не выдаёт права сама по себе.

| Уровень | Право |
| --- | --- |
| 1 | Обработка обращений PERM_REPORT |
| 2 | Модерация PERM_MODERATE |
| 3 | Бан до суток |
| 4 | Бан до месяца |
| 5 | Постоянный бан и управление персоналом |
| 6 | PERM_OWNER |

Флаг event независим от уровня и не заменяет обычные проверки. Наказания и
назначения проверяют иерархию цели. /report имеет лимит и cooldown; /reports,
/accept, /areply и /close обслуживают обращения.

Основатель определяется после bcrypt-входа по зарезервированному аккаунту и
роли уровня 6. Одно совпадение имени не выдаёт полномочия. Для файловой базы
роль имеет заголовок SIGNALADMIN|1 в signal_admins; для SQL используются
существующие таблицы и проверки DBPrimary. /setadmin не заменяет первоначальное
внешнее назначение основателя. tools/bootstrap_founder.py предназначен для
файлового backend, не для обхода SQL-авторизации.

Аудит административных операций пишется в signal_admins/audit.log; ошибки
записи должны рассматриваться как отказ операции там, где требуется аудит.
На Windows устанавливайте бинарные плагины той же архитектуры, что и сервер.

## Ручная приёмка

- Проверить игрока без роли, все шесть уровней, /aduty и независимый event-флаг.
- Проверить /setadmin, запрет наказания старшего и защищённого основателя.
- Открыть панель, переподключить цель с тем же playerid и отправить старый диалог.
- Проверить очередь обращений, санкции, повторный вход и ошибку записи аудита.

Дополнительные команды описаны в ADMIN_TOOLS.md, ADMIN_TOOLS_02.md и
ADMIN_PUNISH_03.md. Статические тесты не заменяют игровую приёмку.
