# Авторизация и файловая совместимость

Регистрация проходит через стандартные диалоги: пароль, подтверждение,
предыстория и начальный регион. До AUTH_READY нельзя войти в игровой мир.
samp-bcrypt вычисляет и проверяет хеш асинхронно с cost 12. Callback сверяет
gAuthToken, состояние и подключение игрока; открытый пароль не записывается.

Штатная сборка CI и Windows определяет TARKENSO_DB_PRIMARY: данные читаются из
MySQL через существующий R41, сохранение аккаунта проверяет row_version.
Установку схемы описывает [db/README.md](../db/README.md).

Без этого определения сохраняется прежний файловый backend. В
scriptfiles/signal_accounts/<имя>.acc используется SIGNAL0317|5. Читаются
также SIGNAL0317|1, |2, |3 и SIGNAL0317|4; после успешного входа старый формат
обновляется. Формат 5 содержит хеш, предысторию, mute_until, деньги, здоровье,
броню, cleaner_paid, txn_serial, статистику гонок и стартовый регион.
Числа, длина хеша и отсутствие лишних строк проверяются до применения.
Сохранение использует временный файл и резервную копию, не выдаёт успешный
результат при ошибке записи. Не смешивайте файловую и SQL-базу вручную.

Ограничитель неудачных входов хранится в памяти: его счётчики и блокировки
сбрасываются при перезапуске. Это не долговременная санкция аккаунта.

## Ручная приёмка

- Проверить регистрацию, несовпавшее подтверждение, три предыстории и региона.
- Войти повторно, проверить bcrypt и блокировку после неверных паролей.
- Отключиться во время hash/verify; старый callback не должен влиять на нового игрока.
- Проверить повреждённый .acc, восстановление backup и отказ записи; затем SQL CAS.
- Проверить миграцию форматов 1–4 и повторный вход с форматом 5.

Для Windows x86 нужны совместимые бинарные компоненты open.mp и samp_bcrypt;
Python-тесты исходников не подтверждают запуск этих компонентов или GTA-клиента.
