# CRIME-UAT-01 — Уведомления о незавершённых заданиях после переподключения

**Проект:** TARKENSO RolePlay Game (open.mp/Pawn).
**Ветка:** `feat/crime02-solo-contract-core`, draft PR #111.

## Зачем

Контракт и его этапы уже хранятся в MySQL; после вылета/релога
игроку не приходило отдельное напоминание. Теперь при **успешной
авторизации и появлении в игровом мире** сервер проверяет
сохранённые данные и однократно выводит в чат состояние задания.

## Поведение

| Состояние при входе | Уведомление |
|---|---|
| Незавершённый контракт, срок не вышел | Номер, название, этап, оставшееся время, `/crime` |
| Незавершённый контракт, время закончилось | Просрочка после успешного SQL-закрытия; открыть `/crime` для истории |
| Открытая тендерная заявка, NPC ещё не выбрал исполнителя | Ожидает решения, примерно сколько осталось, `/crime → Конкурсы предложений` |
| Заявка закрылась за время отсутствия | Окончательное решение через имеющийся `CrimeTender_Finalize`: выигрыш становится текущим контрактом, проигрыш — сообщением |
| Нет активной миссии и заявки | Без лишних сообщений |
| Аккаунт не авторизован или не состоит в криминальном синдикате | Без раскрытия криминальных данных |
| Истёкший контракт при следующем входе | Повторного уведомления **нет**: SQL уже завершил его с записью `EXPIRED` |

Для тендеров после получения груза подсказка учитывает
сохранённые этапы обязательных NPC-встреч: первый связной,
второй связной, затем доставка. Это не даёт пропустить
промежуточные действия.

Существующее время миссии продолжает отсчитываться в офлайне,
дополнительной паузы или продления нет. Изменения
баланса, очков и наград не происходят при простом уведомлении.
Истечение тендерного контракта применяет **существующий**
механизм штрафа один раз по `crime_tender_penalties`.

Напоминание **не является автоматическим телепортом** или
продолжением маршрута. Для игры открыть `/crime → Мой контракт`
или `Маршрут и действие`.

**Точка входа:** `Auth_EnterWorld` **после**
`Leader_OnReady` и `SpawnPlayer`, не `OnPlayerConnect`,
`OnPlayerSpawn` или таймер. Флаг
`gCrimeReconnectNotified` сбрасывается при новом подключении
и отключении. Чужие контракты не выдаются: выборки
ограничены `gDBPrimaryAccountId`, а заявки ещё и
составом синдиката.

## Проверки перед игровым тестом

- `tests/test_crime_reconnect.py`: точка вызова,
  одноразовость, защита SQL и жизненного цикла, работа без
  новой миграции.
- `tests/crime_reconnect_mysql_uat.py`: реальные
  SQL-запросы из Pawn-модуля на отдельной MariaDB,
  восстановление этапа 1/2 после независимого подключения,
  просрочка один раз, ожидание NPC, проигрыш заявки,
  победа одного игрока, отсутствие вторых денег.
- Никаких новых таблиц: последняя миграция №046.

## Ручной чек-лист в GTA

1. Принять обычную миссию, закрыть клиент во время этапа 1
   и войти снова: увидеть в чате название, номер, стадию,
   оставшееся время. В меню задание должно быть доступно.
2. Получить груз (этап 2), отключиться, переподключиться:
   уведомление должно указывать на сохранённый этап 2.
3. Войти позднее срока: сообщение о просрочке,
   **без начисления награды**. Сразу же переподключиться
   ещё раз: старое сообщение не повторяется.
4. Подать тендерную заявку, отключиться на несколько
   секунд и вернуться до выбора NPC: уведомление
   об ожидании. Проверить правильное ограничение по
   одному аккаунту.
5. Подать новую заявку и вернуться уже после окончания
   60-секундного окна: NPC должен завершить конкурс;
   победитель получает доступный контракт,
   проигравший видит результат. При одной заявке
   NPC может выбрать игрока без других участников.
6. Выполнить проверку при смене игрока в том же
   `playerid`, повторном спавне и на гражданском
   аккаунте: никаких утечек или повторных напоминаний.
7. Отключиться посреди физического NPC-эпизода
   тендера и восстановить стадию после входа.
   Геометрию взаимодействия клавишей Y проверять
   отдельно в GTA.

Этот модуль включён в автоматический CI, но игровой
UAT и выпуск в `main` выполняются отдельно.
