# TARKENSO Pawn Static Analyzer — этап 1

**Назначение:** раннее обнаружение **потенциальных** ошибок в исходниках `gamemodes/**/*.pwn` и `gamemodes/**/*.inc`. Проверка выполняется в CI GitHub Actions (`Build`) перед компиляцией, без запуска сервера и без доступа к базе данных.

## Что проверяет

| Идентификатор | Сигнал | Ограничение |
| --- | --- | --- |
| `RESOURCE_UNRELEASED` | `fopen` без видимого `fclose`, `mysql_query` без `cache_delete` в той же функции | Передача владения через другие вызовы требует ручной проверки |
| `RESOURCE_EARLY_RETURN` | Возможный выход из функции до `fclose/cache_delete` | Анализ не доказывает все ветви, guard `if (!handle) return 0` исключён |
| `RESOURCE_UNTRACKED` | `fopen` с неочевидным владельцем | Функциональные обёртки не прослеживаются |
| `TIMER_UNRELEASED` | Повторяющийся `SetTimer/SetTimerEx` без найденного `KillTimer` | Учитывает `KillTimer` во всех анализируемых файлах, но не динамические вызовы |
| `TIMER_UNTRACKED` | Результат повторяющегося таймера не сохранён | Не касается одноразовых таймеров |
| `BUFFER_FORMAT_ARGS` | У `format` отсутствует `maxlength` или форматная строка | Нативный Pawn `format` отличается от C `sprintf` |
| `BUFFER_LENGTH_OVERFLOW` | Литеральный размер `format/strcat/strmid/fread` превышает размер объявленного массива | Пока только числовые размерности |
| `BUFFER_WRONG_SIZEOF` | `format(dst, sizeof(other), ...)` | Не распознаёт намеренные алиасы |
| `BUFFER_REVIEW_BOUND` | `strcat/fread` для массива-параметра без явного размера | Это **повод проверить**, а не доказанная ошибка |
| `CALLBACK_NO_RETURN` | Нет ни одного `return` в `public` | Обязательность возвращаемого значения зависит от контракта |
| `CALLBACK_FALLTHROUGH` | Обнаружен очевидный возможный проход до конца `public` | Не является полноценным анализом графа управления |
| `PLAYER_ASYNC_STATE` | Асинхронно-подобный callback меняет `playerid` без видимого `IsPlayerConnected` | Анализ имён эвристический, альтернативные проверки допустимы |

`foreach` в Pawn не является ресурсом, требующим `close`, поэтому искусственную проверку «незакрытых foreach» не добавляли.

## Режимы запуска

Из корня репозитория:

```bash
python3 tools/check_pawn_static.py --output build/pawn_static_report.json
```

По умолчанию все результаты имеют статус **предупреждений**. Код завершения `0` означает, что сам анализатор выполнился успешно, **а не** что исходники гарантированно безопасны. Сбой анализа (нет исходников, повреждённый UTF-8 и т. п.) возвращает код `2`.

```bash
python3 tools/check_pawn_static.py --strict
```

Опциональный `--strict` возвращает код `1`, если найдена хотя бы одна проблема. **CI не использует строгий режим** на этом этапе.

CI прикрепляет отдельный артефакт `pawn-static-report` (JSON, хранение 7 дней) с полным перечнем проблем. До 60 замечаний выводятся как аннотации GitHub, остальные находятся в JSON.

## Ограничения и план развития

Это лексический анализ с балансировкой скобок и границ функций, **не** Pawn AST и **не** runtime memory profiler. Проверка не доказывает отсутствие утечек, гонок или переполнений. Возможны ложноположительные и ложноотрицательные срабатывания. В частности, вызовы обёрток, передача владения, `#if`, многопутевые ветвления, динамические названия callback и глобальные макросы требуют ручной проверки.

Перед включением блокирующих правил:
1. Сохранить базовый отчёт и сгруппировать предупреждения по правилам.
2. Проверить вручную реальные находки и добавить минимальные регрессионные fixtures.
3. Исключить повторяющиеся ложные срабатывания, задокументировать передачи владения.
4. Переводить в блокирующий режим **только** отдельно подтверждённые типы критических ошибок.

Компиляция без warnings/errors (`tools/check_pawn_output.py`), проверка пересечений ID диалогов и прочие CI-шаги остаются **блокирующими** как прежде.
