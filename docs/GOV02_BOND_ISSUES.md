# GOV-02 — Государственные облигации: выпуск и утверждение

**TARKENSO · Проект GOV-00—GOV-06 · Внутренний этап разработки.**

## Что готово

GOV-02 создаёт полный реестр государственных выпусков без проведения покупок и выплат.
Новые миграции применяются строго последовательно: **017 → 018 → 019 → 020**.
Существующие 017/018/019 не изменялись; GOV-02 — только новая миграция №20.

- `government_bond_issues`: код выпуска, название, назначение, тип, номинал,
  общее и реализованное количество, доходность, условия страхования, сроки,
  состояние размещения, аудируемое подтверждение и версии.
- `government_bond_holdings`: пустой **реестр владельцев** с FK на выпуск
  и аккаунт; в GOV-03 права будут появляться одновременно с покупкой.
- `government_bond_issue_audit`: события CREATE / APPROVE / OPEN / CANCEL.
- `bond_fund_guarantees.released_exposure`: учёт снятого обеспечения
  при отмене **непроданного** выпуска.
- Триггер `government_bond_terms_immutable`: блокирует SQL UPDATE
  экономических условий уже утверждённого выпуска.
- Хранимые процедуры: `gov_bond_issue_create`,
  `gov_bond_issue_approve`, `gov_bond_issue_open`,
  `gov_bond_issue_cancel`.
- `government_bonds.inc`: асинхронный внутренний Pawn API для
  авторизованной тестовой административной сессии. Пока нет публичных
  команд, меню, автоматического размещения или прямого доступа игроков.

## Бизнес-правила

1. Сначала создаётся DRAFT с опубликованным проектом условий.
2. После GOV-05 любой выпуск создаётся в статусе DRAFT и ждёт
   **отдельной подписи** через `/bondsign GOV-000001`. При ранге 2
   специалиста подписывает заместитель или министр. Заместитель (3)
   и министр (4) вправе отдельно подписать **собственный** выпуск:
   вторая персона не требуется, но явное подтверждение обязательно.
3. **В одной транзакции**, под блокировкой казны, утверждаются выпуск
   и `bond_fund_guarantees`; изменяется `bond_fund_committed`,
   пишутся оба журнала. Вызов `bond_fund_commit` отдельно после
   миграции 020 запрещён; он не может создавать «висячие» гарантии.
4. Максимальная страховая ответственность рассчитывается с округлением
   по одной облигации вверх: `ceil(nominal × coverage_bps / 10000) × count`.
   Это консервативно покрывает будущие выплаты каждому владельцу.
5. По умолчанию страховая защита 20%, взнос 2%, грейс 24 ч. Фактические
   значения копируются в выпуск в момент одобрения и **замораживаются**.
6. Новый выпуск нельзя утвердить при выключенном фонде, истёкшем сроке
   размещения, нехватке ёмкости или повторном использовании кода.
7. Открыть продажу можно только для APPROVED в пределах заданного
   реального (UTC) окна. Покупки ещё недоступны до GOV-03.
8. Отменить можно DRAFT / APPROVED / OFFERING, только если проданных
   облигаций **ноль**. При отмене утверждённого выпуска одновременно
   снимается всё резервирование `E`, в реестре гарантий и журнале
   проводится RELEASE. Денежный резерв F **не расходуется**.
9. Отмена проданного выпуска технически запрещена. Реструктуризация
   долга позднее оформляется отдельно, без удаления требований игроков.
10. Все подтверждённые переходы идемпотентны: повтор с тем же event_key
    возвращает прежнее решение, и не резервирует фонд повторно;
    чужой ключ или иное содержание отклоняются.

## Денежные и временные пределы MVP

- `face_value > 0`, `max_quantity > 0`.
- Максимальный объявленный номинал выпуска `face_value × max_quantity ≤ $1 млрд`.
- Доходность фиксируется в базисных пунктах **за весь срок**, а не годовых.
- Размещение не дольше 30 дней, срок после его закрытия не более 365 дней.
- `insured_max_exposure ≤ $1 млрд`, и вместе с другими гарантиями
  не более 80% накопленного фонда.
- Время используется в **UTC**; даты должны явно подаваться в UTC.
- Нет создания денег и автоматического движения средств в GOV-02.

## API (внутренний)

`BondIssues_CreateDraft(playerid, eventKey, issueCode, title, purpose, issueType, faceValue, maxQuantity, yieldBps, start, end, maturity)`

`BondIssues_Approve(playerid,eventKey,issueCode)`

`BondIssues_Open(playerid,eventKey,issueCode)`

`BondIssues_Cancel(playerid,eventKey,issueCode)`

Все методы возвращают булев ответ **о постановке в очередь**,
а не о подтверждении результата. Финальное состояние проверяется в
MySQL, что исключает вывод об успехе по отсутствию ошибки в Pawn.

Временная защита — проверка аккаунта, права `Admin_Allowed(playerid, PERM_MANAGE_STAFF)` и включённого `/aduty`. Два разных высокодоверенных администратора могут создать и утвердить тестовый выпуск.
Это не делегирование роли министра финансов и **не публичный интерфейс**:
GOV-05 использует организацию №5 «Министерство финансов»:
специалисту нужна подпись руководителя, заместителю/министру — нет. Внутренние процедуры выполняются
от имени MySQL-аккаунта сервера и не должны быть доступны пользователям.

**Замечание безопасности:** MySQL `SQL SECURITY INVOKER` пока использует
прямые DML-привилегии сервера. Перед production нужно завершить
пересмотр ограничений привилегий/SQL DEFINER на GOV-06, чтобы
невозможно было обойти процедурные проверки прямым UPDATE.

## Контрольный сценарий

- Существующий фонд F=$150 000, E=$80 000, предел 80% → E_max=$120 000.
- Создаём GOV-A: 10 бумаг по $10 000. Страхование 20% → E_A=$20 000.
- После APPROVE: E=$100 000, F и общий баланс казны **не изменились**.
- Открываем OFFERING, затем отменяем при нулевом количестве проданных.
- После CANCEL: E=$80 000, в `bond_fund_ledger` есть RELEASE -$20 000.
- После любой покупки (появится в GOV-03) такое CANCEL уже невозможно.

## Проверки и выпуск

CI сначала применяет миграции 001,017,018,019 на чистой MariaDB и
проверяет GOV-00/01. Затем выполняет 020 и **GOV-02 UAT**:
покупки отсутствуют, гарантия и статус атомарны, конфликтные повторы
отклоняются, одобрение невозможно самим создателем, проданные выпуски
не отменяются, после подтверждения условия неизменяемы.

Проверяются гонки утверждения, округление лимита по единице бумаги,
а также невозникновение денег при резервировании/освобождении фонда.
Дополнительно обязателен проход CI компиляции Pawn / open.mp.

**Не применять 020 к production.** Пользовательская приёмка только
после завершения GOV-00—GOV-06. PR #94 остаётся draft, код на main не переносим.

**Следующий GOV-03:** реальное размещение, атомарные переводы
покупатель↔казна, страховые взносы, права собственности, график
погашения, требования, дефолты и выплаты из фонда.
