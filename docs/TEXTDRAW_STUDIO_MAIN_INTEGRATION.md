# TextDraw Studio: интеграция полной системы в main

Дата проверки: 27.10.2026. База main —
`5815c376d92ecf0605c65e33dbc785dae141cc88`, включая последнюю правку меню и
камеры корабля. В интеграцию входит вся история TextDraw Studio до
`4af602d6e734433b24c83d620758fc06eb806726`: PR #42, #55, #59, #69, #76 и #78.
Рабочая ветка — `integrate/tdstudio-complete-main-20261027`.

## Состав

Внутриигровой редактор включает проекты MySQL, Global/Player Pawn-экспорт,
клавиатурное перемещение, слои, дублирование, выделение, группы, геометрические
операции, Snap/Grid, историю 20 операций и личные/общие шаблоны.
Используются прежние библиотеки и одно соединение R41. Настройки хостинга
и другие игровые системы не заменяются версиями из старых веток.

Команды:

| Команда | Действие |
| --- | --- |
| `/tdstudio` | главное меню; из preview вернуться к редактированию; при незавершённой клавиатурной операции — отменить её |
| `/tdgrant ID 1` | подтверждённый основатель в /aduty выдаёт доступ до отключения |
| `/tdgrant ID 0` | отозвать доступ и закрыть редактор игрока |

Основателю для входа нужны авторизация, соответствующая роль и `/aduty`.
Остальные действия выполняются в меню, Undo/Redo также доступны на панели.

## Разрешение конфликтов интеграции

- Сохранены все вызовы ShipCam, ShipEditor, AdminFly, сортировки и нового
  профилирования авторизации в lifecycle/callbacks основного мода.
- **TDS-диалоги перенесены с 7100–7147 на 7200–7247**: актуальный main уже
  использует 7100–7105 для ShipPanel. ID корабля не изменены. Вся диспетчеризация
  редактора использует именованные константы; формат проектов/экспорт не затронуты.
- Host-адаптер запрещает открытие и геометрический ввод TDS при активных
  AdminFly, ShipCam или ShipEditor. Включение другого редактора через команду
  также ограничивает прежний TDS_CommandAllowed. После закрытия чужого режима
  доступность TDS восстанавливается. Добавлены исполняемые Pawn-проверки.
- TDS подключается после корабельных адаптеров. Отмена/клики каждого интерфейса
  продолжают идти в собственный обработчик, сортировка остаётся fallback.
- `TDSHost_Message` добавляет `[Tarkenso RPG]` и ограничивает CP1251-сообщение
  144 байтами. Проверено в Pawn. Текст интерфейсов и экспортируемые строки
  сохраняют своё содержимое; префикс относится только к серверному чату.
- Workflow сохраняет аудит стиля чата, новые проверки main, warning gate и
  артефакт `compiled-output`; дополнительно запускает полный Python-набор и
  Pawn-harness TDS с необходимыми 32-битными runtime-библиотеками.
- Уточнены статические тесты под текущий auth profiler, название HUD,
  порядок includes и последовательность миграций 001–016. Защитные проверки
  auth/rollback, миграционных ID и отсутствия пересечения диалогов сохранены.

Исходники ShipCam/ShipEditor/ShipPanel, AdminFly, AuthProfiler и ConsoleRU
совпадают с базовым main. Существующий `012_tdstudio_projects.sql` сохранён
побайтно; он уже присутствовал в main. Новые номера 015/016 не пересекаются
с LoadTest/LoadNet 013/014.

## Обновление сервера

1. Проверить `schema_migrations`. Если отсутствует 012 — применить
   `012_tdstudio_projects.sql` один раз после её предпосылок.
2. Применить отсутствующие `015_tdstudio_groups.sql` и
   `016_tdstudio_templates.sql` по порядку. **Не выполнять повторно** уже
   установленные миграции. Сначала резервная копия, отдельный migration-account.
3. Предоставить прежнему runtime-пользователю CRUD на TDS-таблицах и EXECUTE
   на TDS-процедурах согласно [db/README.md](../db/README.md). Второе подключение
   и новая библиотека не требуются. Рабочая БД этой задачей не изменяется.
4. Установить `compiled.amx`, перезапустить режим и выполнить игровую приёмку.

GTA-клиент при проверке **не подключался**. Compiler, Pawn VM, MySQL/R41,
миграции, асинхронные callbacks, файловый экспорт и новые серверные процессы
реальны; игроки, ввод и TextDraw в harness являются двойниками.

После обновления проверить в игре `/aduty → /tdstudio`, четыре типа элементов,
перемещение/resize/scale с отменой, слои и группы, Undo/Redo, сохранение,
шаблоны и экспорт. Отдельно открыть `/ship`, камеру и редактор корабля, закрыть
их, снова открыть TDS; проверить отсутствие взаимного захвата кликов,
клавиатуры, камеры и управления. Проверить сортировку мусора и русский текст.
Полный список визуальных сценариев приведён в отчётах этапов 3.1–3.3.
