# TARKENSO Load Tester — этап 2: сетевые клиенты

Второй этап существует **отдельно** от игрового модуля /load (NPC).
`tools/loadtest_stage2.py` управляет *настоящими headless SA-MP клиентами*,
позволяя нагружать сетевую авторизацию, загрузку аккаунтов, bcrypt,
синхронизацию игрока и некоторые игровые команды. Он не создает NPC.

## Важные ограничения

В репозитории реализованы **оркестратор**, сценарии TARKENSO (диалоги 6100–6106),
ограничения нагрузки, отчетность и автотесты. Сам клиент RakNet **не написан в
TARKENSO**: используется отдельный проект
[Newmcpe/RakClient](https://github.com/Newmcpe/RakClient) (Rust/Luau).
Он должен быть собран и проверен отдельно. Текущий кандидат:
upstream commit `6ef94b502d4a3bec3f21c318ced731a0131276f4`.
Его README говорит, что он ориентирован на SA-MP 0.3.7/Arizona; **совместимость
с фактическим open.mp, его версией и модом TARKENSO пока не подтверждена
живым подключением**. У upstream есть локально-зависимый патч Rust Recast,
который может мешать сборке на другой машине. Мы не поставляем неподтвержденный
бинарник, не скачиваем и не запускаем произвольный исполняемый код автоматически.

Бот из этого клиента не равен GTA-клиенту по затратам CPU/GPU, но он использует
сетевой протокол, выполняет вход и может присылать игровые RPC (если совместим).

## Как запустить с Windows/PowerShell

1. Убедиться, что игровой сервер принадлежит вам и хостер разрешает
   нагрузочное тестирование. Сделать резервную копию MySQL и игровых данных.
2. Собрать отдельно RakClient и получить `rakclient.exe`. Предварительно
   проверить **один клиент** и совместимость его handshake/dialog/spawn.
3. В папке репозитория выполнить сухую проверку, которая **не подключается
   к серверу**:

```powershell
python tools/loadtest_stage2.py --server 127.0.0.1:7777 --confirm-target 127.0.0.1:7777 --dry-run
```

4. Для внешнего собственного игрового тестового хостинга (замените
   `my-test-host.example:7777` на действительный IP:порт):

```powershell
$env:TARKENSO_LOAD_PASSWORD = "ЗДЕСЬ_ТЕСТОВЫЙ_ПАРОЛЬ_ASCII"
python tools/loadtest_stage2.py --server my-test-host.example:7777 --confirm-target my-test-host.example:7777 --remote-approved --client-bin "./rakclient.exe" --count 1 --seconds 90 --mode register
```

Пароль **не должен совпадать с вашим паролем основателя**. Только тестовые
аккаунты. Пароль читается из окружения и передается непосредственно во временный
локальный Luau-сценарий с ограниченными правами файла. В отчетах пароль не
записывается. Временный сценарий удаляется после теста. На Windows права доступа
к временной папке должны также быть ограничены для других пользователей.

Затем повторный тест уже с существующим тестовым аккаунтом:

```powershell
python tools/loadtest_stage2.py --server my-test-host.example:7777 --confirm-target my-test-host.example:7777 --remote-approved --client-bin "./rakclient.exe" --count 1 --seconds 90 --mode login
```

Пока один клиент не дошел до статуса `spawned`, **не увеличивайте count**.
Для начального испытания подходят значения 5, 10 и 25. Максимум версии:
50 одновременных процессов и 2 новых клиента/с. Ограничения установлены
жестко в скрипте, а не полагаются на аргументы пользователя.

## Режимы

- `--mode register`: для новых тестовых ников `LT_Bot001`, `LT_Bot002` и
  далее; проходит пролог, регистрацию, подтверждение пароля, выбор анкеты
  и региона, подтверждает успешную регистрацию
- `--mode login`: для **существующих** ников с тем же паролем;
  если регистрация предложена вместо логина, сценарий сообщает ошибку
- `--scenario idle`: после спавна остаётся подключённым, обычная
  синхронизация клиента
- `--scenario commands`: после спавна дополнительно отправляет
  `/cleanstats` каждые 30 секунд через SA-MP RPC 50; никаких
  административных, экономических или потенциально разрушающих команд
- `--rate`: подключения/с (по умолчанию 0.5, максимум 2)
- `--prefix`: уникальный префикс для никнеймов тестовых аккаунтов
  (например, `LT_RunA`)

## Отчеты

**Отчеты формируются на ПК, запускающем генератор**, а не в `scriptfiles`
игрового хостинга. Каталог по умолчанию `loadtest_results`:

```
load_net_01_26.10.2026/
  manifest.json
  samples.csv
  LT_Bot001.log
  LT_Bot002.log
```

Снимок `samples.csv` каждые 5 секунд фиксирует:
количество запущенных процессов, `transport_connected`, `game_joined`,
`authenticated`, `spawned`, `exited`, `failed`, `alive`.
Это **наблюдения по клиентским логам**; число запущенных процессов само по
себе не является доказательством входа на сервер. Нулевое число успешных
входов через 30 секунд или ошибка сценария прекращает тест.
По Ctrl+C и по истечении лимита процессы завершаются.

Испытание второй фазы нельзя считать верифицированным до проведения
живого одноклиентного smoke-теста. Обязательно сверяйте клиентские отчеты
с серверным `server_guard.log`, tickrate, SQL latency, CPU/RAM и
фактическим `GetPlayerPoolSize`/числом авторизованных игроков.
Не запускайте генератор на сторонние игровые серверы.
