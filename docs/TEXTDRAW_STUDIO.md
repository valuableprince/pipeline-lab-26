# TARKENSO TextDraw Studio — этап 1

> Историческое описание первого этапа. Текущие хранение, меню и экспорт описаны
> в [TEXTDRAW_STUDIO_STAGE2.md](TEXTDRAW_STUDIO_STAGE2.md).

Внутриигровой редактор на существующем Pawn/open.mp стеке. Клиентские модификации,
новые игровые плагины, таблицы БД и миграции не нужны. Постоянное сохранение и экспорт
Pawn в этот этап не входят.

## Запуск и доступ

Основатель входит в существующий аккаунт с паролем и серверной ролью, включает
`/aduty`, затем вызывает `/tdstudio`. Простого совпадения ника недостаточно:
используются существующая авторизация bcrypt, загруженный аккаунт БД и проверенная
роль основателя (`Studio_Allowed` / `Admin_IsFounder`).

Коллега с любым уровнем администрации, включая нулевой, получает отдельное право
разработчика командой основателя `/tdgrant ID 1`. `/tdgrant ID 0` отзывает право и
сразу закрывает его сессию. Выдача журналируется существующим аудитом; при ошибке
журнала изменение доступа отклоняется. Право привязано к ID аккаунта и токену
текущего подключения, сбрасывается при отключении. Административный уровень 6 у
другого аккаунта сам по себе не открывает редактор. Постоянные роли разработчиков
можно добавить позднее в адаптер доступа.

## Рабочий порядок

1. `/tdstudio` → «Создать проект» → название до 32 символов.
2. «Добавить элемент»: текст, прямоугольник, стандартный TXD-спрайт или модель.
3. Выбрать элемент в списке и изменить свойства. Каждая корректная правка сразу
   обновляет его PlayerTextDraw за открытым диалогом.
4. «Просмотр проекта / холст»: клик по элементу выбирает его; верхняя строка
   показывает ID и координаты. Кнопки `X -`, `X +`, `Y -`, `Y +` перемещают его.
   `STEP` задаёт 0.1 / 1.0 / 5.0 / 10.0. Точные X/Y доступны в свойствах.
5. `MENU` и `ELEMENTS` возвращают к диалогам. ESC с холста открывает главное меню.
6. `PREVIEW` скрывает все служебные TextDraw редактора и отключает его курсор.
   `/tdstudio` возвращает прямо к редактированию.
7. Закрытие редактора требует подтверждения удаления проекта. После закрытия
   повторный `/tdstudio` открывает новую пустую сессию.

Свойство «Выбор мышью» относится к создаваемому интерфейсу. В режиме редактирования
элементы принудительно доступны для выбора, в предпросмотре возвращается значение
модели. Перекрытые, прозрачные и выходящие за экран элементы всегда доступны через
список. Свободного перетаскивания нет: стандартный API передаёт клики, а не надёжный
поток координат курсора.

## Свойства и ограничения

| Свойство | Допустимые значения |
| --- | --- |
| Координаты | X 0..640, Y 0..448; до трёх знаков после точки |
| Размер области | W 0.1..640, H 0.1..448 |
| Размер букв | X 0.01..5, Y 0.01..10; только текст |
| Цвет / Box / фон | восемь HEX-символов RRGGBBAA без префикса |
| Прозрачность основного цвета | 0 — невидим, 255 — непрозрачен |
| Шрифт | 0..3 для текста; 4 для прямоугольника/спрайта, 5 для модели |
| Выравнивание | 1 слева, 2 центр, 3 справа; только текст |
| Текст | до 127 CP1251-символов; русские буквы через уже применяемый rustext |
| Текстовые коды | `~r~ ~g~ ~b~ ~w~ ~y~ ~p~ ~l~ ~h~ ~n~` |
| Box / пропорциональность / выбор | переключатели; Box и пропорциональность только для текста |
| Обводка / тень | 0..4; только текст |
| Спрайты | каталог из шести стандартных `LD_SPAC` / `LD_BEAT` текстур |
| Модели | 411, 560, 26, 2852, 1220, 18633; контролируемый каталог |
| Поворот / масштаб модели | три угла -360..360 и Zoom 0.1..10 |
| Цвета автомобиля | два целых ID 0..255; применяются к автомобильным моделям |

Размер области текста — размер Box/клика, а размер глифов задаётся отдельно.
Рендерер переводит ширину в абсолютную границу для выравнивания слева/справа и
переставляет параметры TextSize для центрированного текста. Прямоугольник
реализован через `LD_SPAC:white`, как фон существующей сортировки.
Для Box высоту видимого фона также определяют размер букв и переносы строк — это
свойство нативного TextDraw, а не независимый прямоугольный виджет.

Все значения проверяются до изменения модели. Не принимаются NaN/Inf, экспоненты,
лишние значения, дробные ID, переполнения, управляющие символы, произвольные
`~k~`-последовательности, цветовые `{...}` вставки и невидимый текст из одних кодов.
Символ `%` передаётся как данные через `%s`, а не как формат native-функции.
Произвольные имена TXD и ID моделей пока не вводятся, каталог расширяется в модели.

## Архитектура и интеграция

| Файл в `gamemodes/includes` | Ответственность |
| --- | --- |
| `tdstudio.inc` | единая точка подключения |
| `tdstudio_model.inc` | данные проекта/элемента, каталоги, строгие парсеры |
| `tdstudio_host.inc` | адаптер авторизации, идентичности аккаунта, аудита и игровых условий |
| `tdstudio_core.inc` | права, выдача доступа, аренда сессий, CRUD, режимы, жизненный цикл |
| `tdstudio_render.inc` | отдельные PlayerTextDraw-хэндлы, преобразование размеров, панель |
| `tdstudio_actions.inc` | применимость и атомарная проверка свойств |
| `tdstudio_ui.inc` | диалоги, карта строк, клики и команды интерфейса |

В пуле восемь независимых сессий, до 64 элементов и девяти служебных PlayerTextDraw
на сессию. Это не выделяет массив элементов на каждый возможный слот сервера.
Идентификаторы элементов возрастают внутри проекта и не переиспользуются после
удаления; индекс массива и native-хэндл не являются ID элемента. Модель не содержит
PlayerTextDraw-хэндлов: её можно сериализовать отдельно от рендера.

Все пользовательские входы повторно проверяют владельца, токен подключения, ID
аккаунта, права, наличие проекта и элемента. Обработчик принимает только ожидаемый
dialogid с серверной картой строк, затем потребляет ответ. Неверные индексы и
клики по неизвестным хэндлам не меняют данные. Лимиты действий — одна операция
интерфейса в 100 мс и открытие командой раз в 500 мс, дополнительно к общему Guard.

На изменение свойства обновляется один существующий PlayerTextDraw; весь проект
не пересоздаётся. Массовый hide/show нужен при смене режимов и их selectability.
Ошибка выделения нового элемента откатывает его создание, частичное создание
панели очищается. Неожиданная потеря уже созданного хэндла закрывает сессию.
Стек/heap Pawn увеличен до 16384 ячеек (64 КБ): ограниченные буферы диалогов
превышают прежний бюджет 4096 ячеек.

Диалоги зарезервированы в диапазоне 7100..7110. Callback-маршрутизация явная,
без ALS-хуков. В `signal0317.pwn` добавлены init/exit, connect/disconnect/death,
диалоги и приоритетные обработчики кликов. `commands.inc` регистрирует две команды
и защищает модальную сессию от посторонних команд. В `waste_sort.inc` добавлена
только проверка занятости интерфейса: одновременная работа сортировки и редактора
невозможна в обоих направлениях. Переключение клавиш не передаётся профессиям,
пока открыт редактор. Закрытие затрагивает только принадлежащие редактору хэндлы.

Целевой SDK: open.mp **1.5.8.3079**, официальный Pawn compiler **3.10.11** из
существующего CI. Существующие includes: Pawn.CMD **3.4.0**, sscanf **2.13.8**,
streamer **2.9.6**. Авторизация и хранение аккаунтов используют прежние
samp_bcrypt / MySQL R41 API; редактор не выполняет SQL-запросов. Серверная версия
на игровом хостинге в этой работе не проверена; старые SA-MP серверы не являются
целевой платформой (используется `PlayerTextDrawSetPos`).

## Проверки

`python3 tools/test_tdstudio.py --server /path/to/open.mp/Server` компилирует
`tests/pawn/tdstudio_harness.pwn` с рабочими includes и запускает отдельный open.mp
процесс на loopback, с отключённым announce и без игровых плагинов/БД.
Игроки, диалоги и TextDraw заменены детерминированными двойниками. Стандартные
операции Pawn/строк/Float выполняются настоящим Pawn runtime. После отчёта
утверждений процесс завершается тестовым драйвером; очистка ядра проверяется
внутри сценария до отчёта. Это проверка поведения кода, не игровая приёмка.

Пять Python-проверок контролируют точки интеграции, отсутствие конфликтов диалогов
и защиту сортировки. Поведенческий сценарий и Python-проверки включены в CI.
Результаты конкретной сборки и оставшаяся ручная приёмка — в
[`TEXTDRAW_STUDIO_VALIDATION.md`](TEXTDRAW_STUDIO_VALIDATION.md).

## Следующий этап

После ручной приёмки: версионированное сохранение модели с проверкой всей загрузки
и атомарной записью; экспорт Global TextDraw/PlayerTextDraw с корректным
экранированием; постоянная отдельная роль разработчика; управление слоями и
Undo/Redo. Хэндлы, владельцы и ожидаемые диалоги в сохраняемый проект не включать.
Перед экспортом проверять общий бюджет TextDraw целевого интерфейса и сервера.

Справка API: [PlayerTextDrawSetPos](https://open.mp/docs/scripting/functions/PlayerTextDrawSetPos),
[PlayerTextDrawTextSize](https://open.mp/docs/scripting/functions/PlayerTextDrawTextSize),
[PlayerTextDrawSetSelectable](https://open.mp/docs/scripting/functions/PlayerTextDrawSetSelectable),
[CancelSelectTextDraw](https://open.mp/docs/scripting/functions/CancelSelectTextDraw).
