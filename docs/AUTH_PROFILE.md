# AUTH-PROFILE-01 — измерение длительности авторизации TARKENSO

Профилировщик **включён постоянно** и автоматически фиксирует этапы
авторизации обычных игроков (кроме NPC) в CSV. Никаких команд, плагинов
или миграций MySQL не требуется.

## Где искать

На игровом хостинге открой `scriptfiles/auth_profiles/YYYY-MM-DD.csv`,
например `scriptfiles/auth_profiles/2026-10-27.csv`. Дата берётся
с серверных часов, а не из часового пояса игрока.

Столбцы:

```csv
unix_time,player_id,session_token,step,duration_ms,ok,tickrate
```

Идентификатор `session_token` позволяет различать повторные входы
одного player_id (значение действует только в текущем процессе сервера).
Имя персонажа, пароль, bcrypt-хеш, IP и персональные данные в файл
**не записываются**.

## Этапы

| step | Что измеряется |
|---|---|
| account_sql_callback | От отправки `mysql_tquery` до вызова его callback, включает очередь и время сети/БД |
| account_row_decode | Обработка и проверка данных аккаунта в Pawn |
| bcrypt_verify_callback | От запроса `bcrypt_verify` до callback, включает очередь и вычисление |
| bcrypt_hash_callback | То же для регистрации |
| camera_stop | Остановка камеры авторизации |
| admin_ready | Проверка администратора, загрузка роли и бана |
| punishment_load | Загрузка административного заключения |
| legacy_account_save | Сохранение устаревшего аккаунта, если применимо |
| leader_ready | Актуализация членства в организации |
| cleaner_ready | Загрузка профиля уборщика и расчёт ожидающей выплаты |
| truck_profile_load | Загрузка профиля водителя муниципального грузовика |
| race_ready | Обновление данных рейтинга гонок, если применимо |
| payday_ready | Синхронизация уровня |
| spawn_request | Подготовка спавна, вызов SpawnPlayer |
| first_spawn_handler | Обработка первого появления персонажа, не обычных респавнов |
| world_enter_sync_total | Общая продолжительность последовательного входа в мир |

`ok=1` означает успешное завершение конкретного измеряемого этапа,
`ok=0` — ошибка. Отсутствующий этап (например `legacy_account_save`)
означает, что соответствующая ветка не выполнялась.

При измерении стадии длительностью **от 100 мс** появляется
короткое предупреждение `[AUTH-PROFILE] slow step=...` в серверном
логе. В обычный игровой чат диагностические сообщения не выводятся.

## Как читать метрики правильно

Это **время от и до** (`GetTickCount`), а не процент загрузки CPU:

- `bcrypt_verify_callback` показывает суммарное ожидание задачи в
  очереди плагина + её выполнение. Сам по себе этот показатель не
  свидетельствует о блокировке игрового потока.
- `account_sql_callback` включает путь через MySQL и возврат
  callback, а не только время SQL-оператора внутри MySQL.
- `admin_ready`, `punishment_load`, `truck_profile_load` и другие
  `*_ready` фиксируют синхронное время Pawn, включая синхронные SQL
  обращения в этих обработчиках.
- `world_enter_sync_total` включает измерения отдельных этапов и
  небольшие затраты на диагностическую запись; сумма этапов необязательно
  равна этому общему показателю.
- CPU% надо смотреть в панели хостинга; если после входа загрузка
  поднимается на доли секунды до 20%, сравни время и фоновые показатели
  из этой панели с данным CSV.

`GetTickCount` имеет миллисекундную точность, поэтому короткие
операции могут давать 0 мс. Файл ведётся постоянно и сохраняется между
перезапусками: **не публикуй его без необходимости**, даже если
персональные поля исключены.

## Первое испытание

1. Загрузи AMX новой версии и полностью перезапусти TARKENSO.
2. Выйди из игры и заново авторизуйся обычным аккаунтом.
3. В панели хостинга проверь CPU в момент ввода пароля и после
   нажатия кнопки «Продолжить».
4. Скачай `scriptfiles/auth_profiles/YYYY-MM-DD.csv` и сравни
   продолжительность `bcrypt_verify_callback`,
   `world_enter_sync_total`, `admin_ready`, `punishment_load`
   и `truck_profile_load`.

Если записи не появились, проверь доступность `scriptfiles`
на запись и лог сервера с префиксом `[AUTH-PROFILE]`.
