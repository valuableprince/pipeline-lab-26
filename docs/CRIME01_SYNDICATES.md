# CRIME-01 — три криминальные организации (первый этап)

Статус: реализация организационной основы в отдельной ветке.
Криминальные контракты, NPC-посредники, казна синдикатов и влияние **не входят** в CRIME-01.
Приоритет всей дальнейшей криминальной системы — одиночная игра и небольшой онлайн.

## Организации

| ID | Рабочее название | Базовая специализация | Ранги |
| --- | --- | --- | --- |
| 6 | Синдикат «Гавань» | Портовая логистика | 1–5 |
| 7 | Консорциум «Вектор» | Экономические связи | 1–5 |
| 8 | Сеть «Орион» | Информация и посредники | 1–5 |

Названия временные и могут быть изменены без миграции ID.
Введены **новые ID 6–8**: существующие организации 1–3,
зарезервированная 4 и Министерство финансов 5 сохраняются без изменений.

## Полномочия и ранги

| Ранг | Название | Текущие права CRIME-01 |
| --- | --- | --- |
| 1 | Новобранец | /fmenu, /fstats, /r, /fleave |
| 2 | Исполнитель | Аналогично рангу 1 |
| 3 | Координатор | Аналогично рангу 2; управление операциями появится в CRIME-02 |
| 4 | Заместитель | /leader, /finvite, /funinvite, /frank (только 1–3) |
| 5 | Лидер | Полное управление составом; только назначение через администратора |

Два заместителя максимум. Лидер единственный. Назначение /setleader и
снятие /unleader доступны администраторам уровня 5+ при /aduty.
Руководитель может назначать сотрудников на ранги 1–4; самовыдача 5
через /frank невозможна. /unleader исключает лидера из состава.
Действующий 30-дневный срок лидерства и /renewleader сохранены.

Шкалы **не смешиваются**: Минфин 1–4, старые организации 1–10,
синдикаты 1–5. Сохранение состава, атомарный откат, аудит, /r,
проверка уникальности членства и ограничение 64 сотрудников
переиспользуют существующий компонент LEADER-01.

## Установка

1. Сделать резервную копию БД и файлов организации.
2. Обновить исходники и собрать новый gamemode.
3. Для MySQL/MariaDB **после 030** однократно применить
   `db/migrations/031_crime_syndicates.sql` с миграционными правами,
   при остановленном игровом сервере. Она добавляет только строки
   `factions` с ID 6, 7, 8 и `schema_migrations=31`.
4. Запустить сервер. В файловом режиме создаются
   `scriptfiles/signal_factions/org_6.dat`, `org_7.dat`, `org_8.dat`.
   В SQL-режиме без миграции фракции останутся **недоступными**.
5. Проверить /leaders и /setleader, а затем /fmenu, /fstats, /r.

SQL-миграция не создаёт новых таблиц; существующие данные и членство
государственных организаций не переносятся и не удаляются.

## Одиночная приёмка

При наличии одного администратора уровня 5+ в /aduty:

1. `/setleader 0 6` — назначить себя лидером «Гавани» (ID 0 — только пример).
2. `/fstats` — показать ранг 5 и название; `/fmenu`, `/leader`
   — открыть интерфейсы.
3. `/frank 0 5` — отказ; ранг 5 нельзя назначить командами состава.
4. `/r Проверка` — увидеть сообщение в своей организации.
5. `/unleader <ник>` — полное увольнение; проверка /fstats.
6. Повторить назначение для ID 7 и 8, проверить /leaders.
7. Проверить сохранение при перезапуске (по одному синдикату).
8. Проверить, что /setleader 0 5 назначает именно министра ранга 4,
   а прежние фракции продолжают использовать максимальный ранг 10.
9. Двумя тестовыми персонажами проверить /finvite → /faccept → /frank 4,
   проверку двух заместителей, увольнение, отсутствие двойного членства.
