Отдельно проверен **ROLLBACK после уже начавшейся вставки элементов**: испорчена
вторая строка, процедура успевает изменить метаданные/удалить старые элементы,
но CHECK вызывает исключение. После отката прежние имя, ревизия и количество
элементов совпадают с исходными. Проверены недоступность чужого проекта и CASCADE.
Отказ временного PlayerTextDraw при загрузке сохраняет прежнюю модель и хэндлы;
закрытие экспорта удаляет временный файл. Итоговый счётчик всех созданных и
удалённых принадлежащих редактору хэндлов совпадает, ошибочных обращений нет.

После timeout не сбрасывается dirty, а backend-слот удерживается до ответа или
ошибки. Повторный запрос той же аренды сессии не ставится в очередь. Проверено,
что поздний ответ не меняет проект и не помечает его сохранённым.

## Воспроизведение

Нужны распакованный SDK 1.5.8.3079 с qawno и components, работающий **тестовый**
MySQL 8.0.16+, mysql CLI и пакет R41-4 с `plugins/mysql.so` и `log-core.so`.
Новых игровых/питоновских библиотек для этих тестов не устанавливается.

Подготовить отдельную БД, например `tds_test_editor`, и пользователя с правами на
неё (CREATE/DROP, CRUD, CREATE ROUTINE и EXECUTE). Для старого R41 использовать
поддерживаемую сервером схему аутентификации; тест использовал mysql_native_password.
Заполнить локальный INI формата существующего `config/mysql.ini.example`, указав
именно тестовую БД. Не использовать конфигурацию рабочего сервера.

```sh
python3 tools/test_tdstudio.py --server /path/to/open.mp/Server
python3 tools/test_tdstudio_stage2.py \
  --server /path/to/open.mp/Server \
  --plugin /path/to/mysql-R41-4-Debian \
  --mysql-config /path/to/test-only-mysql.ini \
  --mysql-client /path/to/mysql
```

Второй запускатель **удаляет и создаёт указанную тестовую БД**; имена вне
`tds_test*` отвергаются до запроса. Он применяет миграции 001..012, создаёт три
тестовых аккаунта, запускает первый сценарий, SQL-проверки отката/прав/параметров,
затем новый процесс с тестом восстановления. `--prefix` позволяет запускать
32-битные compiler/server через эмулятор при необходимости.

Артефакты по умолчанию в `build`: основной compiler.log, журнал MySQL-сценария
`tdstudio-mysql-run.log`, журнал нового процесса `tdstudio-restart-run.log`,
`tdstudio-export-compile.log`, реальные `.inc/.txt`, тестовый `.pwn` и его `.amx`
в `tdstudio-exports`. Credentials не печатаются и в Git не добавляются.

Изменений CI/CD сверх уже добавленных первым этапом нет: существующий CI собирает
основной мод, запускает первый Pawn-сценарий и Python-контракты. Настоящий
MySQL-сценарий выполнен локально и предоставлен как воспроизводимый запускатель.

## Что остаётся ручным / не проверено

- Реальные области клика, визуальное совпадение слоёв/моделей/Box и русский текст
  на GTA-клиенте после загрузки и интеграции экспорта.
- Регистрация, авторизация и мини-игра сортировки с реальными игроками после
  установки AMX; автоматические проверки не заменяют игровую приёмку.
- Применение миграции и права CREATE ROUTINE/EXECUTE на игровом хостинге.
- Полный `gmx` рабочего мода с подключёнными игроками; протестирован рестарт
  изолированного open.mp-сценария, не production-сервера.
- Рестарт самого MySQL, реальный сетевой обрыв в точке COMMIT, длительное
  восстановление соединения и права файловой системы хостинга.

Полный исторический набор unittest не зелёный: отсутствующие старые документы и
workflow-файлы дают 24 ошибки, старые контракты БД/HUD/гонок/пролога — 9 провалов.
Их идентификаторы сравнивались до/после и не изменились. Новые тесты проходят.
PR не сливается автоматически; третий этап не начат.
