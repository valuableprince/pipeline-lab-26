# SHIP-MAP-01: грузовой пирс SF, Tarkenso RolePlay Game

Issue: [#126](https://github.com/valuableprince/pipeline-lab-26/issues/126).
**Статус привязки: `NEEDS_IN_GAME_SURVEY`. По умолчанию маппинг отключён.**

Готова целая локальная сцена: Г-образный пирс с рабочей площадкой **288×63u**,
западным въездом **27×72u**, прямой северной причальной линией **288u**,
контейнерным двором, одним настоящим портовым краном, двумя портовыми
техническими/складскими помещениями, парковкой, промышленным освещением,
парными швартовочными столбиками, резиновыми отбойниками и доковыми барьерами.
Это статический маппинг без новых работ, транспорта, экономики или SQL.

Изображение из Issue задаёт композицию. Оно **не является источником координат**.
Точки `-1450 / 1490..1550` не использованы. Нулевые `BASE_X/Y/Z` в исходнике —
пустые настройки, а не предложенная площадка в SF. Код блокирует включение,
пока разработчик явно не настроит начало координат.

## Локальная геометрия и точные позиции

`gamemodes/includes/ship_sf_pier_map.inc` содержит единственный построитель сцены.
Локальное начало `(0,0,0)` — юго-западный угол основной площадки **на уровне
проезжей поверхности**. `+X` идёт вдоль причала, `+Y` — к открытой воде. При
`BASE_ROT=0` длинная сторона направлена запад–восток, швартовка с севера.
Поворот — yaw геометрии, а не навигационный heading корабля.

Преобразование всех pivots, включая стены и декор:

```text
world_x = BASE_X + local_x*cos(ROT) - local_y*sin(ROT)
world_y = BASE_Y + local_x*sin(ROT) + local_y*cos(ROT)
world_z = BASE_Z + local_z
world_rz = ROT + local_rz
```

В таблице ниже координаты — **центры collision AABB по X/Y**, `bottom` — низ
коллизии относительно поверхности. `SFPM_Centre` и `SFPM_OnFloor` автоматически
вычитают повёрнутое смещение pivot. Это не произвольное `Z = height / 2`.
Полный реестр pivots/min/max находится в `gSFPierModels`.

## Подъезд, корабль и границы расчётной проверки

Проезжая поверхность плоская. После съёмки `BASE_Z` нужно совместить с высотой
**дорожного покрытия**, а не с координатой Z игрока/автомобиля. Въезд занимает
X=0..27, Y=-72..0. До установки настроек нельзя утверждать, что он доходит до
существующей дороги. Если дорога выше/ниже или удалена дальше, сначала исправить
длину/профиль подключения по фактическим точкам. Не соединять перепад ступенью
и не объявлять ровный въезд проверенным без проезда. Длину можно менять через
`SF_PIER_APPROACH_ROWS` (кратность 9u; при превышении 512 объектов сцена целиком
откатывается); наклонный пандус требует фактических отметок, сейчас его нет.

Зарезервированы непрерывный въезд (чистая полоса X=5..22), центральный проезд
Y=24..40, разворотная площадка X=218..266, Y=5..53 (**48×48u**) и пешеходная
полоса Y=52..55. В 9-метровом причальном фартуке стоят отдельные опоры света;
он не объявляется полностью свободным от оборудования. Въезд и поворот не
перекрываются контейнерами/помещениями. Проходимость полуприцепа на скорости,
коллизии шин и края плит проверяются только игровым клиентом.

Корпус 9585 по collision данным занимает относительно собственного pivot:
X=-115.640625..114.359375, Y=-17.710937..18.437500, Z=-14.125..11.679687.
Длина **230u**, ширина **36.148437u**. Проверка 12 штатных деталей текущей
`Ship_CreateCargoAssembly` сохраняет этот X/Y, но верх 9584 достигает Z=47.468737
относительно корня. Кастомная сохранённая сборка может отличаться.

Для **геометрического теста сцены**, не для автосохранения корабля: локальный
корень `(144,88.711)`, yaw=0, даёт корпус X≈28.359..258.359, Y≈71..107.148.
От северной грани пирса до борта 8u; по длине остаётся около 29u с каждого конца.
Кран находится восточнее этого корпуса, стрела направлена в сторону воды;
он не анимируется и не гарантирует охват всей палубы. Последнюю швартовочную
станцию сдвинули на X=282, чтобы она не попала в AABB крана.

Тест проверяет **весь** объём корпуса с запасом 2u и непрерывные swept boxes
для отвода на +20u по локальной Y, затем +300u по X. Он проверяет только новую
сцену, не стандартные берег/воду/мосты/дороги/LOD и не существующий маршрут.
**Поворот, подход, береговая стыковка и весь рейс не сертифицированы.**
Этот пример не является новым маршрутом и не должен заменять сохранённые точки.

## Включение превью и штатная загрузка

`streamer.inc` v2.9.6 уже подключён в режиме. Плагин streamer должен быть установлен
для сервера (см. [STREAMER.md](STREAMER.md)). Мир **0**, interior **0**, все игроки;
stream distance=450u, draw distance=350u. Основание имеет priority=20, декор=0,
чтобы при ограничении клиентского бюджета раньше подгружалась опорная поверхность.
Глобальные streamer-лимиты и видимость других карт код не меняет.

1. На отдельном тестовом сервере снять точки въезда, берега, северной кромки и
   границы безопасной воды. До включения занести реальные значения в определения
   **перед** `#include "ship_sf_pier_map.inc"` в `signal0317.pwn`:

   ```pawn
   #define SF_PIER_MAP_MODE (1)
   #define SF_PIER_SITE_CONFIGURED (1)
   // Подставить числа из игры: это НЕ готовые мировые координаты.
   #define SF_PIER_BASE_X (surveyed_x)
   #define SF_PIER_BASE_Y (surveyed_y)
   #define SF_PIER_BASE_Z (road_surface_z)
   #define SF_PIER_BASE_ROT (surveyed_mesh_yaw)
   ```

   Имена `surveyed_x` и прочие выше — обозначения для замены числами. Они
   намеренно не компилируются как готовая конфигурация. Режим 1 пишет в лог
   `NEEDS_IN_GAME_SURVEY`. Не включать в действующем мире до осмотра конфликтов.
2. Пересобрать обычным `tools/build_windows.py` или CI. В тестовом `OnGameModeInit`
   **после** успешного `ShipSFPierMap_Init` можно однократно вызвать
   `ShipSFPierMap_Export();`. В `scriptfiles/ship_sf_pier/preview_objects.inc`
   появятся все 496 реальных `CreateDynamicObject` с мировыми pivots/углами и
   материалами. Это готовый Pawn-фрагмент для отдельного просмотра/импорта,
   без алгоритма генерации. Не загружать одновременно фрагмент и модуль.
3. Превью создаётся один раз в `OnGameModeInit`, очищается в `OnGameModeExit`.
   Повторный Init не создаёт копий. Отказ любого объекта или материала уничтожает
   весь созданный комплект, повторный запуск возможен. Обработчиков reconnect нет.
4. Для отключения вернуть `SF_PIER_MAP_MODE=0` и перезапустить тестовый режим.
   Для принятой после UAT привязки: реальные BASE, `SF_PIER_SITE_CONFIGURED=1`,
   `SF_PIER_SITE_VERIFIED=1`, `SF_PIER_MAP_MODE=2`. Без verified режим 2 запрещён
   препроцессором. Это переключатель сборки, без новой команды/API для игроков.

## Проверки и ручная приёмка

Автоматически, без GTA-клиента:

```bash
python3 -m unittest discover -s tests -v

python3 tools/check_dialog_ids.py
```

Последняя команда компилирует OFF/PREVIEW/VERIFIED и экспортированный Pawn,
проверяет запрет включения без настроек/верификации, затем запускает настоящий
Pawn-код в локальном open.mp с doubles streamer. Выполняются отказы **каждого**
из 496 созданий и 678 material-операций, откат, повторный Init/Shutdown, retry,
